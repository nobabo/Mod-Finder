- Skyrim Special Edition: Nexus `skyrimspecialedition`. Do not reuse original Skyrim Workshop IDs.

Unsupported combinations have no search requests or misleading fallback URLs. Add new games only after verifying source IDs, game editions, and actual Workshop availability.

## Thunderstore direct search (2026-09-25)

The shared Node/Workers adapter calls `GET https://thunderstore.io/api/cyberstorm/listing/{community}/` anonymously, only when a user searches or requests another page. Supported communities are Lethal Company (`lethal-company`), Valheim (`valheim`), and Risk of Rain 2 (`riskofrain2`). No full-package feed, index, database, API key, archive download or shared search cache is involved.

The official implementation searches package name, owner name and description. It returns 20 results/page. The deprecated `experimental/frontend` endpoint is not used. `popular` maps to `most-downloaded`; the default and `updated` map to `last-updated`. The Thunderstore tab exposes only popular/updated sorting, preserving upstream order (including upstream pinned items). Combined searches request updated results from Thunderstore. Unsupported version/loader/kind filters are reported, and unknown game compatibility stays null.

Identity is community plus `namespace-name`, with both segments validated. Cursors are bound to game/source/query/sort/filters, and only a bounded page number is accepted. Upstream next URLs are never fetched. Existing 4-second timeout, 4 MiB response bound, 20-item schema bound, 429 cooldown and source disable switch apply. Search responses are `no-store`. Explicit favorites/comparison continue using the user's existing local storage; automatic persistence and shared caches are not enabled.

Live checks: `node scripts/verify-thunderstore.mjs [API-origin]` checks all three games, original packages, nonoverlapping pages, zero results and native-origin CORS. `scripts/verify-ui.js` checks the current interface with deterministic search responses through Playwright CLI. Native installers are not regenerated by this integration; production native builds must use the deployed HTTPS API.

## Nexus public search (2026-09-25)

At the user's explicit request, the external-only project rule and loopback/development activation flag were removed. Web and native clients now use the normal search API, whose Nexus adapter queries the official anonymous GraphQL endpoint. Personal keys are neither required nor forwarded. The old browser-only test module and its flag are removed.

Search is scoped to the catalog's Nexus game domain, matches mod names, requests at most 20 items, and supports relevance/downloads/updated sorting. Cursors are bound to the complete search with offsets bounded to 10,000. Cross-game data and GraphQL partial errors fail closed; unknown compatibility remains null. Unsupported filters are reported. Existing timeout, body-size bounds, rate-limit handling and DISABLED_SOURCES=nexus apply. No user login, archives, background index or server cache is involved. The official GraphQL API is still in development; this integration is not a claim of Nexus application registration.

Verification uses tests/nexus.test.ts, scripts/verify-nexus.mjs and the normal production/Workers checks. The public service includes Nexus results in combined search. Account-specific authentication remains outside this search integration.

## Data handling

No mod archives are fetched or hosted. Icons load from original HTTPS URLs. External navigation has a hostname allowlist in both shared code and native capabilities. Only normal text descriptions are rendered. Search strings are not in application logs, but production reverse proxies must also omit/redact query strings. No server database, search cache, or background index is used.
